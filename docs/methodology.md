# Methodology v0.1

## Evaluation unit

An evaluation unit is one unedited deck generated by one identifiable product configuration for one benchmark task. A submission is invalid if the native artifact, run metadata, or exact prompt is missing.

## Tracks

Version 0.1 contains only `prompt_to_deck`. Future tracks will cover `document_to_deck` and `deck_editing`; results from different tracks must not share a single rank.

## Evaluation layers

### 1. Deterministic artifact inspection

The inspector parses the OOXML presentation and reports observable properties:

- slide and object counts;
- editable text, image, chart, table, and group counts;
- text density and minimum detected font size;
- objects outside the slide canvas;
- pairwise bounding-box overlaps as a review queue;
- low-resolution raster images based on effective display DPI;
- speaker notes and basic typography consistency.

Overlap and overflow findings are deliberately named `risk` signals. Decorative overlap can be intentional, and text fit depends on rendering engines and installed fonts. These signals must not be treated as aesthetic ground truth.

### 2. Rubric-based expert review

Reviewers score six independent dimensions from 1 to 5:

1. content quality;
2. narrative quality;
3. visual quality;
4. instruction following;
5. editability;
6. user experience.

Every task also includes binary, task-specific checks. These checks prevent a polished but incomplete deck from receiving an inflated score.

### 3. Blinded pairwise preference

Two decks produced for the same task are shown without product identity. Left/right placement is randomized. Reviewers separately choose the better deck for content, visual design, and immediate usability. Ties are allowed.

Pairwise results should be aggregated by track and scenario using a Bradley–Terry model once the sample is large enough. Elo may be published as a live, clearly labeled provisional score.

## Main-track generation protocol

- Exact prompt and assets supplied by the benchmark.
- Product interface language set to Chinese when supported.
- Default theme and generation settings.
- One successful generation attempt.
- No manual edits after generation.
- A retry is allowed only for a technical failure and must be logged.
- Native output is preferred. PDF-only or image-only products remain eligible but receive structurally accurate editability measurements rather than imputed scores.

## Reporting

Results are segmented by task, scenario, artifact type, product plan, and run date. The public view displays dimension scores by default. An optional composite score may be calculated only with published weights and must never replace raw dimensions.

## Recommended composite for v0.1

When a single sortable value is necessary:

| Dimension | Weight |
|---|---:|
| Content quality | 25% |
| Narrative quality | 20% |
| Visual quality | 20% |
| Instruction following | 15% |
| Editability | 10% |
| User experience | 10% |

The benchmark additionally publishes an unweighted score and all individual dimensions.

## Known limitations

- Fonts and rendering engines can change line breaks.
- Closed products may change without version identifiers.
- Automated metrics can be gamed and do not establish taste.
- Human preferences vary by profession and region.
- The initial Chinese task set is not representative of every language or presentation culture.
